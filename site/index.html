How to run

怎么跑

Both routes call the same command — the workflow is just CI wrapping the CLI. Nothing has to be installed to read a result: a published run lands in results/latest.json and shows up on this page.

两条路调的是同一条命令，工作流只是替你在 CI 里包了一层 CLI；看结果不需要装任何东西——发布的 run 落在 results/latest.json，本页直接显示。

① On GitHub Actions

① 在 GitHub Actions 上

  1. Fork the repo, or push your own clone to GitHub.
  2. Settings → Secrets and variables → Actions → New repository secret: name MODEL_API_KEY, value your OpenAI-compatible key.
  3. Actions → run-eval → Run workflow, then fill the inputs: item_path = items/bench10, model = models.example.yaml, judge = manual (or llm), leave publish_results checked.
  4. The job validates every item first, scores them, and fails rather than publish a partial run. With publish_results on, it commits results/latest.json and latest.md back to the repo — that is what the section above reads.
  1. Fork 本仓库，或把自己的 clone 推上 GitHub。
  2. Settings → Secrets and variables → Actions → New repository secret：名字填 MODEL_API_KEY，值是你的 OpenAI 兼容 key。
  3. Actions → run-eval → Run workflow，填输入：item_path 填 items/bench10，model 填 models.example.yaml， judge 选 manual（或 llm）， publish_results 保持勾选。
  4. job 先校验全部题目再逐题打分，出现报错就整单失败、不会发布半份结果。勾了 publish_results 会把 results/latest.json 与 latest.md 提交回仓库——也就是上面那一段读的数据。

② On your machine

② 在本地

Python 3.11+ and an OpenAI-compatible key. Output lands in runs/latest/ — results.json for per-item scores, report.md for the readable report.

需要 Python 3.11+ 和一个 OpenAI 兼容 key。结果写在 runs/latest/：results.json 是逐题得分， report.md 是可读报告。
